# 正方教务抢课工具开发文档

本文档描述当前代码的实际设计与实现，不回写早期开发计划中的过时方案。

参考资料：

- [znjhahaha/zhengfang-api](https://github.com/znjhahaha/zhengfang-api)，核对日期 2026-10-21，commit `71e1dc0`
- 本项目真实浏览器抓包与 HAR

参考仓库以太原科技大学为例，只用于核对接口类型和参数结构。不同学校的正方版本在 URL、字段和登录链路上存在差异，项目不能直接写死单所学校的数据。

## 1. 设计目标

工具分为两个阶段：

1. **准备阶段**：完成登录，保存 Cookie，尽可能提前采集学生上下文、接口路径和请求模板。
2. **运行阶段**：使用准备好的会话轮询课程；命中目标后获取动态数据并提交，直到服务器返回成功。

设计原则：

- 用户手动完成验证码、扫码等认证动作，工具不绕过身份认证。
- Cookie 与请求模板分开保存。
- 准备阶段只收集当前可获得的数据，不等待选课开放。
- `xkkz_id`、`do_jxb_id` 等动态数据在运行时获取。
- 干跑和实跑严格分离：
  - `node rob.js --dryrun`：只查询、匹配、记录。
  - `node rob.js`：允许实际提交选课。
- 所有账号统一使用 `accounts[]`，单账号也是只有一个元素的账号数组。

### 2.1 敏感文件

- `config/config.json`：学校地址、账号密码、目标课程等。
- `state/<id>.state.json`：Playwright `storageState`，包含 Cookie 和 localStorage。
- `state/<id>.templates.json`：真实请求模板，可能包含学号、姓名、课程和加密 ID。

上述文件默认权限为 `0600`，不得提交或发送给不可信的人。

```json
  "selectionPath": "/xsxk/zzxkyzb_cxZzxkYzbIndex.html",
  "gnmkdm": "N253512",
  "authMode": "auto",
  "accounts": [
    {
      "id": "account1",
      "login": {
        "username": "",
        "password": ""
      },
      "targets": {
        "kch": "207786",
        "kw": "摄影",
        "njdm_id": "2025"
      }
    }
  ],
  "notify": {
    "webhook": "",
    "beep": true
  }
}
```

### 4.1 账号文件默认路径

```text
state/<id>.state.json
state/<id>.templates.json
logs/<id>.log
logs/<id>.debug.log
```

顶层字段作为公共默认值，账号字段覆盖顶层字段。

### 4.2 目标匹配

- `kch`：课程号精确匹配。
- `jxb`：教学班短 ID 精确匹配，忽略大小写。
- `kw`：课程名或教学班名包含关键词。
- `njdm_id`：可选年级过滤。

多个目标之间是“或”关系。第一门成功选上的目标会结束本次运行。

## 5. CLI 约定

### 5.1 准备

```bash
node rob.js --prepare --sso wengine
node rob.js --prepare --sso zfsoft
```

- `wengine`：先进入反向代理/WEngine，再走 SSO。
- `zfsoft`：使用正方原生登录入口。
- `--force-login`：不载入旧 Cookie。
- 多账号默认串行准备，一个账号完成后自动准备下一个。

准备阶段：

1. 打开登录入口。
2. 等待用户完成认证。
3. 进入正方教务系统后一次性保存 Cookie。
4. 尝试提取学生上下文。
5. 自动尝试触发查询，收集当前能获得的模板。
6. 保存已有结果，关闭浏览器并退出。

如果当前不是选课阶段，可以没有 `query/detail/submit` 等模板。准备仍可成功，动态数据在运行时获取。

### 5.2 运行

```bash
node rob.js --dryrun
node rob.js
```

- `--dryrun`：只查询和匹配，不提交选课。
- 不带参数：实跑，命中目标后进入提交流水线。

以下参数已经移除：

- `--prewarm`
- `--dry-run`
- `--dryrun=false`
- `--no-dryrun`
- 配置中的 `dryRun`

指定这些参数会直接报错，避免误把实跑当成干跑。

### 5.3 诊断

```bash
node rob.js --capture
node rob.js --import-har FILE
node rob.js --list-accounts
node rob.js --debug --prepare --sso wengine
```

### 5.4 清理

```bash
node rob.js --delete
```

清理默认配置、`state/`、`logs/` 和旧版根目录运行时文件。该命令必须单独使用。

## 6. 登录与 Cookie

### 6.1 登录链路

反向代理场景通常为：

```text
正方 SSO 入口
  -> WEngine 应用认证平台
  -> CAS / 企业微信
  -> WEngine token-login
  -> 正方 ticketlogin
  -> 教务门户 / 选课页
```

实现处理：

- WEngine 登录页的“统一认证”入口。
- CAS 扫码或账号密码表单。
- iframe 和页面跳转中的表单。
- WEngine 将正方静态资源改写后触发的 CSP 问题。
- WEngine 回跳后仍落到 `login_slogin.html` 时，再次进入 SSO 接入口。

### 6.2 Cookie 保存

- 只在进入正方教务系统后保存。
- 每个进程只采集一次。
- 写入 Playwright `storageState` 格式。
- 文件权限设为 `0600`。
- 不在日志中输出 Cookie 值。

### 6.3 启动校验

普通运行必须有有效 Cookie。模板不是硬性启动条件，因为：

- 选课开放前可能没有学生上下文。
- `xkkz_id` 和 `do_jxb_id` 只能在运行时获取。

## 7. 静态准备与动态获取

| 数据 | 准备阶段 | 运行阶段 |
|---|---|---|
| Cookie / storageState | 可以 | 复用 |
| 教务门户访问权限 | 可以 | 复用 |
| 页面隐藏学生字段 | 能取得就保存 | 缺失时轮询选课页提取 |
| 接口路径 | 能抓到就保存 | 使用配置/默认/HAR 路径 |
| `query` 请求模板 | 能触发查询就保存 | 构造或补齐并保存 |
| `xkkz_id` | 当前可见就保存 | 从查询结果或页面动态更新 |
| `do_jxb_id` | 不适合长期保存 | 命中课程后实时获取 |
| 已选列表模板 | 能抓到就保存 | 缺失时使用 `ctx` 兜底 |
| 退选模板 | 只有真实退选时才能抓 | 缺失时使用构造参数 |

### 7.1 运行时上下文引导

如果 `templates.ctx` 不存在，运行循环会定期 GET 选课页，并从以下来源解析：

- hidden input 的 `name/value`
- 页面全局变量
- inline script / `onclick` 中的赋值
- 网络请求中的完整表单

必要字段包括：

```text
bh_id jg_id zyh_id zyfx_id njdm_id
xz ccdm xbm mzm xslbdm xsbj
xkxnm xkxqm xkly xklc rwlx kklxdm xkkz_id
```

当前未开放选课时，页面只显示“当前不属于选课阶段”，此时继续轮询即可。

### 7.2 运行时模板补齐

第一次查询后：

- 如果 `templates.query` 缺失，保存本次实际构造的查询参数。
- 从响应顶层或 `tmpList[].xkgz` 中提取 `xkkz_id`。
- 更新后的模板以 `0600` 权限写回。

## 8. 接口核对

### 8.1 参考仓库接口

参考仓库以太原科技大学为例，记录：

| 功能 | 方法 | 路径 |
|---|---|---|
| 当前用户信息 | GET | `/jwglxt/xtgl/index_cxYhxxIndex.html` |
| 选课首页 | GET | `/jwglxt/xsxk/zzxkyzb_cxZzxkYzbIndex.html` |
| 课程列表 | POST | `/jwglxt/xsxk/zzxkyzb_cxZzxkYzbPartDisplay.html` |
| 提交选课 | POST | `/jwglxt/xsxk/zzxkyzbjk_xkBcZyZzxkYzb.html` |
| 已选课程 | POST | `/jwglxt/xsxk/zzxkyzb_cxZzxkYzbChoosedDisplay.html` |
| 课表 | POST | `/jwglxt/kbcx/xskbcx_cxXsgrkb.html` |
| 成绩 | POST | `/jwglxt/cjcx/cjcx_cxXsgrcj.html` |

本工具只实现选课闭环需要的接口，不实现成绩和课表模块。

### 8.2 本项目接口抽象

| 逻辑类型 | 用途 |
|---|---|
| `index` | 选课入口 / 上下文页面 |
| `display` | 初始课程区加载 |
| `query` | 课程列表查询 |
| `detail` | 获取教学班 `do_jxb_id` |
| `title` | 可选的提交前置探针 |
| `submit` | 真正提交选课 |
| `choosed` | 已选课程 |
| `drop` | 退选 |
| `batch` | 退选后刷新批次 |

路径优先级：

```text
config.api
  > HAR / 浏览器抓包学到的路径
  > indexPath
  > lib/api.js 默认路径
```

### 8.3 与参考仓库的差异

1. 参考仓库说明课程列表可能直接返回 `do_jxb_id`。本项目支持：
   - 列表已有 `do_jxb_id`：直接使用，跳过详情请求。
   - 列表没有：调用 detail 接口获取。
2. 参考仓库列举了 `rwlx=1`、`sxbj=1`、`kklxdm=01` 等参数。这些是学校/轮次相关值，本项目优先使用真实模板，只有缺失时才补默认值。
3. 参考仓库未展开详情接口，但部分正方部署必须先调用 `cxJxbWithKchZzxkYzb` 才能拿到加密教学班 ID。
4. 已选接口存在 HTML 和 JSON 两种版本，本项目同时解析 `Choosed.html` 和 `ChoosedDisplay.html`。
5. 本项目额外实现冲突检测、只退可选修课、退选后重新获取加密 ID。

### 8.4 会话失效

以下情况视为会话失效：

- HTML 返回登录页。
- JSON `code/statusCode/status` 为 `901` 或 `910`。
- 消息包含“用户登录”“请先登录”“未登录”。

运行会停止并提示重新 `--prepare`。

## 9. 请求模板

### 9.1 模板结构

```json
{
  "ctx": {},
  "display": {},
  "query": {},
  "detail": {},
  "submit": {},
  "drop": {},
  "choosed": {},
  "xkkz": "",
  "api": {},
  "meta": {},
  "responses": {}
}
```

### 9.2 `ctx`

学生上下文，决定请求能否通过服务端的身份和培养方案校验。

### 9.3 `query`

课程列表查询参数。缺失时由 `buildQueryParams()` 使用 `ctx` 和默认字段构造。

### 9.4 `detail`

教学班详情模板。缺失时使用 query/display/ctx 构造，并实时取得加密 ID。

### 9.5 `submit`

真实提交模板。缺失时使用兜底字段，但字段可能因版本不同而不完整。实跑前应尽量通过 HAR 或真实提交补齐。

### 9.6 `xkkz`

当前选课控制 ID。来源于：

- 请求模板
- 页面 hidden input
- inline script
- 查询响应顶层
- `tmpList[].xkgz` 的规则串

## 10. 运行状态机

```text
INIT
  -> LOAD_CONFIG
  -> PREPARE 或 LOAD_PREPARED_STATE
  -> LOAD_SESSION
  -> WAIT_CONTEXT
  -> QUERY
  -> MATCH
  -> DRY_RUN_STOP
     或
  -> ALREADY_CHOSEN
     或
  -> FETCH_DETAIL
  -> TITLE_PROBE
  -> SUBMIT
  -> FAILED -> COOLDOWN -> QUERY
     或
  -> SUCCESS -> EXIT
```

### 10.1 轮询策略

- 查询无结果：下一轮继续。
- 查询异常：记录后下一轮继续。
- 名额满：冷却后继续。
- 详情暂不可用：冷却后继续。
- 提交失败：冷却后继续。
- 提交成功或确认已选：立即停止轮询。
- 会话失效、维护页面：停止并提示人工处理。

## 11. 选课流水线

```text
PartDisplay
  -> 匹配课程
  -> 已选检测
  -> 若列表无 do_jxb_id，调用 detail
  -> 可选 title 探针
  -> submit
  -> flag=1 成功
```

### 11.1 双重教学班 ID

- `jxb_id`：短教学班 ID，主要用于匹配。
- `do_jxb_id`：长加密 ID，用于真正提交。

不同部署可能从列表或详情接口返回 `do_jxb_id`。加密值可能一次有效，不能长期缓存。

### 11.2 提交成功判定

满足任一条件视为成功：

- `flag == "1"`
- `success == true`
- 响应为数字 `1`
- 消息明确包含“成功”，且不包含“失败/未成功”

### 11.3 失败处理

- 普通失败：30 秒冷却。
- 无可用教学班：60 秒冷却。
- 冲突：进入冲突处理。
- 可恢复异常：下一轮继续。

## 12. 冲突处理

安全规则：

- 只有 `kklxdm=10` 且 `rwlx=2` 的课程允许自动退选。
- 必修课、无法解析时间、无法找到冲突源：只告警。
- 退选后刷新批次并重新获取 `do_jxb_id`。
- 重新提交仍失败：进入冷却，不循环误退。

退选不可逆。实跑前必须先干跑确认匹配和已选列表解析正确。

## 13. HAR 分析

### 13.1 输入

读取 `har.log.entries[]`：

- URL、method、headers
- `postData`
- response status、headers、body

### 13.2 识别顺序

1. URL 规则识别。
2. URL 不匹配时，根据请求体推断。
3. 请求体仍无法识别时，根据响应体推断。
4. `Display` 返回 `tmpList` 时重新归类为 `query`。
5. 数组响应结合 pending request 区分 `choosed` 和 `detail`。

### 13.3 模板选择

同一接口出现多次时，保留字段更多的请求体，而不是简单覆盖为最后一条。

### 13.4 写入

```bash
node rob.js --import-har 选课.har --account account1
```

输出：

```text
state/account1.templates.json
```

有效的 HAR 必须包含选课阶段 XHR。只有登录页、静态资源和 CAS 页面无法分析出课程接口。

## 14. 日志与退出码

| 退出码 | 含义 |
|---|---|
| `0` | 正常完成 |
| `1` | 一般异常或准备失败 |
| `2` | 会话过期 |
| `3` | 配置不完整 |
| `4` | Cookie 缺失或已准备会话无法复用 |

日志同步写入文件，避免进程退出时丢失最后一条错误。

## 15. 多账号

- 准备：串行，一次只打开一个浏览器。
- 运行：按 `concurrency` 并发。
- 每个账号独立 Cookie、模板、日志和冷却状态。
- 一个账号失败不会阻止后续账号准备。

## 16. 安全约束

- 不绕过验证码、扫码、MFA 或校方权限。
- 不保存 Cookie 值到日志。
- 不保存 `Authorization`、`Cookie`、`Set-Cookie` 到模板。
- 模板文件权限 `0600`。
- 冲突自动退选严格限制为可退选修课。
- `--delete` 必须单独使用。
- 查询间隔不建议低于 1.5 秒。

## 17. 测试与扩展

运行：

```bash
npm test
```

当前测试覆盖：

- 目标解析与匹配
- 查询/详情/提交参数构造
- 已选 HTML 解析
- 接口路径分类
- HAR 分析与未知路径推断
- 配置和多账号路径
- supervisor 参数传递
- 冲突安全规则

新增学校适配时优先：

1. 配置真实 `base/loginPath/selectionPath/api`。
2. 用 `--capture` 或 HAR 获得真实请求。
3. 检查 `state/<id>.templates.json` 是否包含 `ctx/query/detail/submit/choosed`。
4. 先使用 `--dryrun`。
5. 确认匹配、已选列表和冲突解析后，再运行 `node rob.js`。

## 18. 已知限制

- 不同学校字段和加密规则不完全一致。
- `submit/drop` 必须尽量来自真实请求模板，否则只能使用兜底参数。
- 当前未选课阶段可能无法提前取得学生上下文，运行时会轮询。
- 系统维护、未开放轮次、权限限制无法由客户端绕过。
- 选课结果始终以教务系统返回为准。
