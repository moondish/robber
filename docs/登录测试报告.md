## 失败项

### 1. 选课页 URL 可以被误判为已登录

位置：`rob.js:923`、`rob.js:990`。

复现：在选课页 URL 返回登录表单，调用 `isInAcademicSystem(page)`。

预期：返回 false；实际：返回 true。`ensureSelectionPage` 也在检查页面挑战前直接接受选课 URL。

原因：仅通过 URL 包含选课路径判断成功，没有先检查页面内容。若站点直接在原 URL 展示登录表单，后续可能尝试保存尚未认证的会话；本用例直接验证了状态判断函数的误判。

建议：检查登录表单或认证状态后，再确认进入教务系统。

### 2. CAS 在新标签页打开时无法继续预填

位置：`rob.js:896`、`rob.js:1100`、`rob.js:1109`。

复现：反代页面的 `#cas-login` 链接设置 `target="_blank"`。

预期：切到新标签页填写并完成认证；实际：新标签页已请求 `/cas/login`，但程序仍在原反代页寻找表单，最终超时。

原因：新页面事件只绑定采集与调试，登录主流程一直使用原来的 `page`。

建议：处理 popup/new-page，将后续登录与状态检测切到实际认证页面。

### 3. 扫码页切换账号登录时可能点中父容器

位置：`rob.js:717`。

复现：包含“账号登录”按钮的父 div 也能通过 `textContent` 匹配该文字。

预期：点击按钮，展开表单并预填；实际：优先点击父 div，表单仍隐藏，用户名和密码为空。

原因：候选同时包含 div/span，按文档顺序找到第一个文字匹配项就点击。

建议：优先选择可见且可交互的切换控件，点击后确认表单出现。

### 4. 隐藏的首个密码框会遮蔽后面的可见表单

位置：`rob.js:649`。

复现：DOM 中第一个密码框隐藏，后面有可见密码框；账号输入框使用预填逻辑支持的 `name="account"`，按钮为普通按钮。

预期：识别可见表单并预填；实际：没有识别到表单，账号和密码均未填入。

原因：探测阶段只对 `querySelector` 返回的第一个匹配元素检查可见性，而且账号选择器比实际填充阶段更少。

建议：遍历所有匹配项寻找可见输入框，统一探测与填充所支持的选择器。

## 安装问题

执行 `npm ci --no-audit --no-fund` 后，npm 自动执行 `package.json:9` 的 `prepare` 生命周期脚本，也就是 `node rob.js --prepare`。

刚克隆的仓库没有真实配置，命令因找不到 `config.json` 而以退出码 1 结束。此次依赖已在该错误之前安装完成，浏览器测试能够运行。

建议：将交互登录命令从 npm 的 `prepare` 生命周期移出。测试环境可用 `npm ci --ignore-scripts` 绕过生命周期；此命令为建议，未在本次测试中另行执行。
