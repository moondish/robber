# 选课接口抓包清单

> 这是**维护者适配清单**，不是普通用户的使用前提。普通用户只需要配置 `base`、`login`、`targets` 并登录；缺失接口由维护者根据提供的 JS/HAR 补齐。

目标：拿到页面真实使用的接口路径、请求参数和响应结构，写进 `state/templates.json`，让脚本不依赖写死的旧路径。

> 不同学校、不同正方版本的中文方法名基本一致，但 URL 前缀、参数名、是否需要前置探针会变。**以你抓到的真实请求为准**，不要只改域名。

## 二、每个请求要记录哪些细节

对上面每个请求，右键 → Copy → **Copy as cURL**，或者在 DevTools 里查看：

1. **Request URL**：完整路径，不要只记方法名。注意是否带 `?gnmkdm=N253512`。
2. **Request Method**：通常是 `POST`，但也可能是 `GET`。
3. **Request Headers**：`Content-Type`、`X-Requested-With`、`Origin`、`Referer`、`Accept`。如果系统有自定义 token（如 `X-CSRF-Token`、`X-Token`），也要保留。
4. **Request Payload / Form Data**：**全部字段**。正方使用 `key[0]=value` 这种数组格式，复制时不要漏括号。
5. **Response**：完整 JSON。提交失败时尤其要保留 `msg`，冲突处理依赖它。
6. **Cookie**：只需要知道有 `JSESSIONID` 和 `route` 两个会话 cookie；不要把 cookie 明文发到公开仓库。

## 三、用项目自带的抓包模式

这是最省事的方式：

```bash
node rob.js --capture
```

浏览器打开后：

1. 手动登录，进入选课页。
2. 点一次“查询”，确认列表出来。
3. 对一门课点“展开/选课”，让详情请求发出。
4. 如果要适配提交/退选，再实际提交一次（建议先用 `--dryrun` 观察，或选一门不重要的课）。
5. 回到终端按 Enter。

程序会把识别到的接口路径、请求模板、响应样例写入对应账号的 `state/<id>.templates.json`，并打印：

```text
接口映射: {"query":"/xsxk/...","detail":"/xsxk/...","submit":"/xsxk/..."}
```

多账号配置下要指定账号，否则会报错：

```bash
node rob.js --capture --account a1
node rob.js --import-har 选课.har --account a1
```

把对应账号的 templates 文件发回来即可。它**不包含 Cookie/Authorization**，但可能包含学号、姓名、课程信息，发送前请自行确认。

## 四、用 DevTools 导出 HAR

如果不想跑项目自带抓包：

1. 打开选课页，F12 → Network。
2. 勾选 `Preserve log` 和 `Disable cache`。
3. 清空网络记录。
4. 完成上面的 1–5 步操作。
5. 在 Network 面板空白处右键 → **Save all as HAR with content**。
6. 把 HAR 放到项目目录，运行：

```bash
node rob.js --import-har 你的文件.har
```

程序会自动识别并写入 `state/templates.json`。如果识别到的接口不全，HAR 里通常缺了对应的 XHR，或者请求体/响应体没有被保存。

## 五、路径不一致时怎么改

抓到的路径和默认值不同，有两种方式：

### 方式 A：让程序自动学（推荐）

直接跑 `--capture` 或 `--import-har`，识别到的路径会写进 `state/templates.json` 的 `api` 字段。`config/config.json` 里显式填写的 `api` 优先级更高；留空时使用抓包结果。

### 方式 B：在 `config/config.json` 手动覆盖

```json
"api": {
  "display": "/xsxk/你的初始展示接口.html?gnmkdm=N253512",
  "query": "/xsxk/你的查询接口.html?gnmkdm=N253512",
  "detail": "/xsxk/你的详情接口.html?gnmkdm=N253512",
  "submit": "/xsxk/你的提交接口.html?gnmkdm=N253512",
  "choosed": "/xsxk/你的已选接口.html?gnmkdm=N253512",
  "drop": "/xsxk/你的退选接口.html?gnmkdm=N253512",
  "title": "/xsxk/你的前置探针.html?gnmkdm=N253512",
  "batch": "/xsxk/你的批次刷新.html?gnmkdm=N253512"
}
```

路径可以写相对 `base` 的 `/xsxk/...`，也可以写完整 `http(s)://...`。没有的接口留空或删掉。

## 六、发送前脱敏

可以保留：

- URL、方法名、参数名、JSON 字段名、`flag`/`msg` 结构；
- `do_jxb_id` 的**格式**（例如长度、是否十六进制）；
- 课程号、教学班号（如果不在意隐私）。

建议替换：

- `JSESSIONID`、`route`、任何 `Authorization`/token；
- 学号、姓名、身份证号、手机号；
- 完整 cookie 和密码。

最稳妥的做法是直接发送 `state/templates.json`（项目已经排除了 cookie 和认证头），再附一张选课页截图。

## 七、判断抓包是否够用

`state/templates.json` 里应至少出现：

```json
{
  "ctx": { "bh_id": "...", "jg_id": "...", "njdm_id": "..." },
  "query": { "kklxdm": "10", "kspage": "1", "...": "..." },
  "detail": { "kch_id": "...", "xkkz_id": "...", "...": "..." },
  "submit": { "jxb_ids": "...", "kch_id": "...", "...": "..." },
  "api": {
    "query": "/xsxk/...",
    "detail": "/xsxk/...",
    "submit": "/xsxk/..."
  }
}
```

如果 `query` 有、`detail` 没有：详情请求没触发，回到页面点一次课程展开。

如果 `detail` 有、`submit` 没有：没有真正提交过，抓包时至少点一次“选课”，或用 `config/config.json` 里的兜底参数先干跑验证。

如果 `submit` 有、但响应一直 `flag=0`：先看 `msg`。名额满、时间冲突、不在选课轮次、会话过期是四类不同问题，不要盲目重试。
